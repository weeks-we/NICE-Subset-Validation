```text

先读当前项目 AGENTS.md、README.md、docs/METHOD.md、docs/DATA.md、docs/HANDOFF.md，

当前唯一正式配置是 configs/main.yaml，唯一服务器交接是 docs/HANDOFF.md。
当前 A 实验保持原定义；RSI 是待单独冻结的新设计。
本次允许的执行范围，以用户最新明确指定的模块、CPU/mock/server 模式与预算为准。
不要因为任务卡中包含后续模块，就自行扩大到真实 GPU 或未来实验。

你的职责是完成当前已授权阶段的实现、验证和交付，不只给建议或伪代码。
先盘点已有能力，复用经过验证的梯度、训练、判分和恢复接口。
发现用户已有修改先保留；不要覆写无关改动。
一次围绕一个工作包交付；可以继续当前已授权范围内的后续模块，维护状态清单。
默认顺序实施，不自行启动多个 Codex 子代理。

必须遵守：
1. 本地只做 CPU、微型随机模型与显式 mock，不下载目标权重或启动 GPU/Docker。
2. 研究代码变化跑全量 pytest；流程变化另做全尺寸 fresh mock、串行评分对照、恢复、audit、CSV/PNG 和 zip 检查。
3. 真实模型、完整长度反向、GPU 容量和官方容器必须服务器实测；mock 不作正式结论。
4. 新真实实验使用新 clone、新 venv、新 storage；只复用核验的基座/tokenizer、原始数据、来源锁和下载缓存。

8. 不替用户 commit/push/merge；数据、权重、缓存、凭据、状态和本地报告不进入 Git。
9. 正常路径、端口、依赖和已授权工程问题自主解决。只有新增研究范围/费用授权、实际权限或不可解决的外部阻塞才集中报告。
10. 不夸大实现状态：分别说明 CPU、mock、server smoke、正式研究结果。

每个模块执行：
读取现状 → 列出影响文件 → 实现最小完整能力 → 独立参考验收 → 运行适用检查 → 留下交接。
模块完成标准以计划书第 6 节和当前任务卡为准，不以“代码已写完”为准。
未验收的模块不能标完成；负结果可以是完整研究结果。

将执行状态、证据和本地报告写到新的 Git 忽略 runs 子目录。
规格与源码变更保持可审阅，记录新 design 接入对当前 A 的影响。
未取得 RSI 新协议执行授权前，不把 proposed/draft 配置升级为正式入口。

每次交接给出：模块与状态、实际改动/运行、证据路径与身份、适用检查、未完成/阻塞/协议偏离、下一步。
```
