## 1. 先明确研究目标和执行范围

最终研究问题是：**同一个模型能否根据自身任务表现与学习历史，持续修订可执行的数据筛选程序；这种修订是否改善学习；任务模型的参数更新是否进一步改善其选择控制能力。**

推荐分三层完成，按证据逐层推进：

| 层次 | 必须回答的问题 | 通过后允许的结论 |
|---|---|---|
| A：前置有效性 | 当前 NICE 高低组，在固定训练与选权重规则下有何差异？交互、梯度、训练、判分是否可信？ | 当前设置下的 NICE 风格选样诊断；不直接推出完整 RSI 有效 |
| R1：反馈驱动筛选 | 持续修订程序是否超过随机、直接 NICE、固定程序、只刷新分数和预设课程？ | 有证据时可称反馈驱动的自主数据筛选有效 |
| R2：控制能力迁移 | 固定学生、证据、历史和预算，仅替换控制器权重后，选出的数据是否更有用？ | 只有这层证据支持时，才主张参数更新改善了选择控制能力 |

不要直接从当前高低组实验跳到“递归自改进已经成立”。也不要在代理估值没有基本校准、工具链尚未验收时，先堆完整多角色循环。

## 4. RSI 扩展的协议草案

以下是推荐默认设计，必须在试点后形成带 checksum 的正式协议；未冻结字段不应被 Codex 自行填成正式参数。

### 4.1 模型、角色与状态

每次外层尝试 t 从已接受模型 θ_t 开始。任务模型、Lopt、Lexec、Leval 都绑定这个模型身份，分别使用独立 prompt 和记忆视图。一轮内全部冻结。Lopt 生成程序；Lexec 调用确定性算子执行器；Leval 调用数值评估器并解释结果。

上述共享身份要求适用于 Ours 的正常运行。FC 和 E5 是预先登记的控制器权重对照，允许显式指定不同的 role ModelRef；必须同时记录学生与各角色身份。特征、能力报告与训练父模型始终绑定被评价的学生，不能因更换 Lopt 就误用该控制器的梯度缓存。

**模型生成的自然语言不得替代数值评估或官方判分。** Lexec 不能通过“理解程序”自由修改成员；Leval 不能自行编造分数。确定性执行器和检查器是权威，角色负责提出、调用、分析。

内层只搜索程序与子集，不更新 adapter。外层仅对选出的一个子集做一次预算受限 SFT，产生 θ′。完成开发评测后原子接受或拒绝：

```text
accepted θ_t
  → 开发任务执行与分技能报告
  → Lopt 提议 → DSL 校验 → Lexec 物化 → 特征服务 → Leval
  → 内层返回 best_feasible(program, 实际评价过的 subset)
  → 从 θ_t 分支 SFT 得到 θ′
  → 同开发任务配对评测
  → 接受：θ_(t+1)=θ′，角色与任务模型一起切换
     拒绝：θ_(t+1)=θ_t，保留失败反馈，参数与父优化器状态不被污染
```

这三个研究角色不意味着需要让三个 Codex 子代理并行改仓库。实现阶段默认一次完成一个工作包。

### 4.2 数据与历史曝光隔离

| 集合 | 作用 | 可被控制器看到什么 |
|---|---|---|
| P_train | 成功完整轨迹候选池 | 轨迹、技能标签、证据、长度、允许的模型侧特征 |
| D_dev | 内层目标梯度、能力报告、外层接受/拒绝 | 同一开发集反复使用，必须明确属于适配性评测 |
| D_probe（推荐） | E1 代理校准、试点方差与超参选择 | 只作为开发证据；一旦用来改设计，就永远不算最终独立测试 |
| D_final | 所有方法的最终确认性比较 | 搜索、训练、接受决策和超参冻结前不能获得题面、标签或运行反馈 |
| D_smoke | 容器与接口开发验收 | 固定开发题，可反复检查，绝不进入研究指标 |

D_dev 同时用于目标梯度和接受/拒绝，遵循研究原稿；这会产生适配性，报告必须承认。不要把它改个名字称独立验证。D_probe 不是绕开独立测试限制的第二个 final。

所有集合按 ID、显式来源家族闭包、精确和近似题面隔离；训练候选对所有评测集合排除。技能标签只从准许的题面、轨迹和证据产生，不能把评测测试补丁、标准修复答案送入控制器。开发工具中正常获得的测试观察按协议保留。

M00 建立 `exposure_registry`：登记旧运行和人工已查看过的 Verified 任务、用途、日期及来源家族。RSI 的确认性 D_final 应排除已用于 A 的 NICE、选样诊断、调参与已查看 benchmark 的任务及相关家族。即使文件名是 `test`，只要曾用于决策就按已暴露处理。来源不足或曝光历史不完整时，必须说明无法保证新 final 盲测，并提出新来源方案；不能自动改用已看过的题。

数据规模暂不机械沿用 20/100：先检查每个技能样本数、成功方向覆盖和历史排除后的可用量。A 的 20 题仅用于 A；不假装它天然足以支持多技能保持约束。

### 4.3 技能标签与证据

建议初始技能：问题定位、代码理解、实现修改、测试验证、失败恢复。它们是待人工审计的标签体系，不是“模型真实能力维度”的既定事实。

每条轨迹允许多标签，保存标签版本、生成方式、置信度、证据消息下标或原文区间。题目层面的技能分组在运行前固定，不能按模型是否成功重新分类。每种技能的有效题目数、跨标签重叠和 unknown 比例必须报告。

先分层抽取少量轨迹人工审计，再决定是否扩大自动标注。不要训练一个新的大型标签模型作为前置条件。标签不足时允许 unknown，不能由 LLM 猜测补齐并当成可信证据。

### 4.4 梯度代理：先定清楚估什么

建议第一版沿用 A 的 LoRA 损失、成功奖励、固定 rollout 分母、任务内归一化与 CountSketch 逻辑，增加技能维度。定义：

```text
h_v = (1/M) Σ_m resolved(v,m) · ∇_LoRA NLL(实际生成 tokens | 实际输入)
d_i = fresh_adam(clip(∇_LoRA mean_assistant_CE(轨迹 i)))
q_ik = 在技能 k 的全部固定任务 v 上，平均 cos(P(d_i), P(h_v))
U(S) = Σ_k w_k · mean_{i∈S} q_ik
```

P 为共享确定性投影。失败 rollout 贡献 0 但仍除以 M；零方向任务仍保留在该技能固定题目分母中。NaN、缺失结果、基础设施错误不伪装成零向量。

第一版明确采用“样本方向分数的子集均值”作为排序代理；它不等于真实多个 Adam 更新的学习增益，也不能把“先逐样本 fresh-Adam 再平均”称为“batch 梯度做 Adam”。可加一个 batch 级诊断来量化偏差，但正式使用哪个代理必须先冻结。数据等权与 token 等权也不得混用。

零方向技能如何处理：先保留零向量并报告 coverage；若所有目标方向为零则停止该轮，不靠 loss 代理偷偷替代。技能方向过少时发出低覆盖警告，并限制相关能力结论。

质量、预算、来源上限、去重、最低技能覆盖由确定性硬约束检查。若加入软惩罚，其公式、量纲和权重必须冻结，不能由 Leval 的文字解释动态改变。

### 4.5 每阶段训练与公平预算

推荐 RSI 第一版：每次候选训练从当前 accepted adapter 开始，**每阶段重置优化器为 fresh AdamW**，在该阶段内正常持续更新；所有对照同样重置。这样与 fresh 方向代理的局部假设较接近。它仍是代理，不等于真实多步 Adam。若改为继承 Adam moments，必须另立协议、绑定 moments 身份并重新做 E1；不能把 fresh 代理说成继承状态的准确更新方向。

A 的优化器和独立起点规则不因此改变。新方案须冻结 weight decay、eps、clip、学习率、LoRA 配置、物理 batch、有效 batch、每阶段更新数或停止规则。

RSI 主比较按实际 assistant 监督 token 预算匹配，不只按样本条数。建议用完整轨迹、无重复抽取、成员数为有效 batch 的整数倍，每个阶段在选中轨迹上仅训练一遍。目标 token 误差建议先取 ±2%，但应在试点前验证可行性并于正式实验前冻结；不能通过截断轨迹、屏蔽监督 token 或暗增 epoch 凑齐预算。

若“完整轨迹、batch 整除、技能下限、token 匹配”无法同时满足，返回不可行及冲突项。先在试点调整共同预算或约束，再冻结；正式运行期间不能单独为 Ours 放宽条件。

必须区分三类成本：被接受训练的 token、所有候选训练实际执行的 token、总资源成本。拒绝分支的训练也计入实际训练和总成本。同 token 对照以所有尝试实际执行的监督 token 为主要预算轴，同时报告最终接受链 token；不能把拒绝成本藏起来后宣称训练预算相等。

### 4.6 外层接受/拒绝的推荐规则

第一版推荐可解释的确定性规则，不做“LLM 觉得有进步就接受”：

```text
accept = (目标任务宏平均成功率提升 ≥ δ_target)
         AND (每个预先指定保持技能的下降 ≤ δ_keep[k])
         AND (证据、预算、结果完整性全部通过)
```

按相同固定任务做配对比较；多标签技能分母固定。δ_target、δ_keep、最低有效任务数和无结果处理必须写入协议。试点可用“至少多解决 1 个目标任务，保持技能不丢已解决任务”的保守规则验证事务；这只是工程试点默认值，不能在未知样本量时承诺它适合正式研究。

每个方法共享最大外层尝试次数 T，而不是“直到接受 T 次”。拒绝仍消耗一次尝试。达到次数、总成本、无可行子集或预先定义的停滞条件即停止。不得无限补训直到 Ours 成功。只改历史记忆、不改模型，也必须留下不同的 state identity。

跨阶段是否允许重用已训练轨迹须在 M02 冻结。推荐 Ours 与动态对照采用统一的显式曝光上限，并登记每条轨迹的累计曝光；S0 固定子集重复分阶段训练属于预先声明的对照定义。由此产生的重复数据与新数据比例是结果的一部分，不可在实现中悄悄去重掉 S0 后续阶段。每阶段“一遍”指本阶段子集各曝光一次，不代表跨整个 accepted 链每条轨迹只曝光一次。

### 4.7 内层停止与无效程序

内层预算包括总程序提案数、三角色所有生成 token、工具调用、梯度新计算量、GPU 时间与墙钟，不只计 Lopt 调用。无效程序和修复尝试同样占预算。

试点建议上限：每个外层尝试最多评价 8 个程序、连续 2 个可行候选无超过 ε 的改善即停；ε 可先用 1e-4 做工程检查。正式值应根据代理尺度和计时冻结，以上数字不是已授权正式规模。

返回的是历史最好**实际物化并评估过**的可行子集，不能最后再让模型描述一个更好的未执行程序。效用平分使用固定规则，例如先 token 偏差更小、再 canonical hash；不可按事后真实训练成绩倒选内层候选。

## 5. 程序与模块之间的数据契约

### 5.1 拟建结构

```text
nice_validation/rsi/
  contracts.py       数据对象与状态校验
  registry.py        模型、证据、曝光与发布身份
  skills.py          标签与证据审计
  evaluation.py      分技能开发评测与报告
  features.py        按 checkpoint 隔离的梯度特征
  program.py         DSL schema、canonicalize、类型检查
  operators.py       纯函数算子与确定性物化
  utility.py         代理目标和约束评估
  roles.py           角色 prompt、工具权限与调用记录
  search.py          内层搜索与 best_feasible
  outer.py           候选训练、接受/拒绝事务
  baselines.py       共享接口的对照选择器
  schedule.py        新设计的阶段调度
  reporting.py       统计、审计与交付
```

文件可以根据实际依赖适度合并；上述职责、接口和测试边界必须保留。不要为凑目录创建只有占位符的模块。

### 5.2 必须显式传递的对象

| 对象 | 最低字段 |
|---|---|
| ExperimentSpec | schema/design 版本、模型/源码/环境/数据锁、全部预算、split hash、方法表、停止/接受/统计规则 |
| ModelRef | base lock、adapter tree hash、父 ModelRef、LoRA 参数签名、训练与优化器策略身份 |
| CapabilityReport | ModelRef、split hash、逐题结果引用、分技能分母/成功数、stop_reason、token/时间、覆盖率 |
| FeatureKey | 模型与 adapter、tokenizer/template、mask/loss、原始样本及实际 tokens/labels、参数顺序、投影、数值配置 |
| ValidationFeatureKey | FeatureKey 的模型/数值部分，另加开发 split、实际 rollout/input/output IDs、奖励与技能标签版本 |
| Program | schema/operator registry 版本、输入池 hash、AST、显式 seed、预算与约束引用 |
| Selection | program hash、按顺序的成员 ID、实际 token/label hash、监督 token 数、分布/约束报告、subset hash |
| EvalReport | ModelRef、Selection、feature key、效用组成、硬约束结果、缓存命中与本次成本 |
| RoundState | method/replicate/attempt、accepted ModelRef、role refs、独立记忆 hash、best selection、预算余额 |
| TrainReceipt | 父/子 ModelRef、实际训练行 hash、优化器重置策略、RNG/order、逐步断点、实际 token/更新数 |
| AcceptanceDecision | 前后 CapabilityReport、固定规则值、每项比较、接受/拒绝、发布后的 accepted ref |
| CostRecord | 范围、开始结束、UUID、GPU 时间、输入/输出/监督 token、缓存、失败/拒绝归属、未知字段 null |

缓存键不能只有 task_id 或模型名称。推理切换 adapter 后必须核验所有服务和角色实际加载的 adapter hash；不能只改日志里的 checkpoint 字符串。

建议接口：

```python
materialize(program, pool, context) -> Selection | Infeasible
evaluate_selection(selection, feature_store, utility_spec) -> EvalReport
search_round(state, role_runtime, budgets) -> SearchResult
train_candidate(parent_model, selection, train_spec) -> TrainReceipt
decide(parent_report, candidate_report, acceptance_spec) -> AcceptanceDecision
publish_acceptance(decision, expected_parent_hash) -> RoundState
```

### 5.3 第一版 DSL 的能力边界

用带版本的 JSON AST 表达程序，禁止直接执行模型生成的 Python、shell、SQL 或导入任意模块。程序只选择已有轨迹，不生成或改写教师训练文本。

第一批算子即可覆盖核心研究问题：

| 算子 | 含义 | 必须保留的约束 |
|---|---|---|
| filter | 按已登记质量、长度、技能、证据字段筛选 | 字段和比较符白名单；unknown 策略显式 |
| score | 选择 NICE/技能方向/已登记静态信号组合 | 特征模型身份一致；不从文本自由生成分数 |
| rank / take | 稳定排序与截取 | 并列按固定 ID；无自动补齐 |
| deduplicate | 按固定任务/家族/近似规则去重 | 记录被排除成员与理由 |
| branch | 在不同技能或条件下形成子集 | 限制深度、节点数与重复分支 |
| mix / quota | 分配技能、来源或保持数据配额 | quota 单位明确是条数还是监督 token |
| pack_budget | 完整轨迹下匹配 token 与 batch 整除 | 解不出即不可行；确定性求解或固定 seed |
| order | 决定最终训练顺序 | 成员与顺序分开记录；不允许暗中重复曝光 |

JSON 结构示意，最终以 M05 的 schema 为准：

```json
{
  "schema_version": "rsi-program-v1",
  "pool_sha256": "<frozen-pool-hash>",
  "seed": 11,
  "pipeline": [
    {"op": "filter", "field": "quality_pass", "cmp": "eq", "value": true},
    {"op": "branch", "branches": [
      {"skill": "failure_recovery", "pipeline": [
        {"op": "filter", "field": "recovery_evidence", "cmp": "eq", "value": true},
        {"op": "rank", "feature": "nice:failure_recovery", "descending": true}
      ]},
      {"skill": "retention", "pipeline": [
        {"op": "rank", "feature": "nice:retention", "descending": true}
      ]}
    ]},
    {"op": "mix", "quota_ref": "<frozen-quota-spec>"},
    {"op": "deduplicate", "rule_ref": "<frozen-dedup-spec>"},
    {"op": "pack_budget", "budget_ref": "<frozen-stage-budget>"}
  ]
}
```

需要证明顺序确实产生不同结果：例如“先按家族去重再取前 k”和“先取前 k 再去重”在有重复家族的池中可能不同。测试必须覆盖这种语义差异，不能编译后把所有算子偷偷排序为固定顺序。

## 6. 分模块实施清单

每个模块都按“读取实际状态 → 实现最小完整能力 → 验收 → 留下交接证据”完成。工作包以依赖和验收为单位，不按一天写完若干文件来估进度。下列测试是针对研究语义、数据完整性和恢复风险；文档排版等低影响改动不增加无意义测试。

### M00｜范围、证据与缺口盘点

- **输入**：本计划依据文档、当前源码、配置、现有运行目录清单。
- **行动**：读取项目约束；列出工作树用户已有修改；建立“已实现/CPU 已验/服务器待验/未实现”矩阵。核对 A 当前服务器状态，不能把本地历史验证记录当本次服务器完成证据。定位 IDE 的 main-res 文件，核对 run identity 和 checksum；不可访问时如实登记。
- **交付**：`inventory`、`gap_matrix`、`exposure_registry`、冲突和未知项表；本地运行材料放忽略的 `runs/` 下。
- **验收**：每个“已完成”有实际证据路径和身份；历史 30 轮/390 条诊断与当前 75 轮/2060 条设计明确区分；无凭空声明。
- **边界**：只读盘点，不启动 GPU、容器或重判。外部原始证据不可访问不妨碍继续做设计，但阻止宣称相应实测已验收。

### M01｜当前 A 的真实前置验收与执行

- **依赖**：M00；真实阶段须处于用户已授权服务器范围，读取 `docs/HANDOFF.md`。
- **行动**：新 clone/venv/storage；核验可复用模型和原始数据；锁定授权 UUID；完成全部任务环境预检、真实 32k SFT 更新、131072 上下文且 32768 输出位置的 NICE 反向、logprob 重放、adapter 保存重载和开发题官方判分。通过后按现有入口执行 A。
- **交付**：容量、环境、服务、判分 smoke 证据；A 的 selection、CSV/PNG、audit、zip、completion。
- **验收**：第 2 节计数全部吻合；12 节点均验证后才能选四份；原 NICE 题复测完整；无 FAIL。低 coverage WARN 原样保留。
- **失败处理**：OOM 保留峰值与失败位置，不静默缩上下文/输出/模型；全零方向明确停止；同类基础设施错误最多两次重试，模型失败不重试刷成功率。
- **与后续关系**：M02–M10 的隔离 CPU 工作可先准备；A 若未完成，不能把完整 RSI 的可行性写成已证实。A 结果不理想时先检查代理与链路，不能保证它必然支持扩展。

### M02｜RSI 协议、数据角色与成本草案

- **依赖**：M00；利用 M01 可用计时，未知值保留未冻结状态。
- **行动**：将第 4 节转换为严格的 spec schema；确定 D_dev/D_probe/D_final/D_smoke 角色；记录模型、数据与源码锁；为每个方法列公平约束、优化器策略、停止规则、接受阈值和统计主比较。先对拆分规模、token 预算和方法数量做可行性计算。
- **交付**：可校验的 `protocol.draft`、`decision_log`、`split_plan`、按方法的 `cost_estimate`；明确哪些字段仍待试点测量。
- **验收**：缺少 T、token 预算、最终模型清单规则或接受阈值时 real 启动被拒绝；draft 不可伪装 frozen。现有 A 配置与交接不变。
- **冻结节点**：试点前冻结试点协议；M12 后再冻结正式协议。新增服务器研究预算需用户授权一次，不将常规实现或错误修复拆成重复审批。

### M03｜数据台账、技能标签与来源证据

- **依赖**：M02 的角色定义。
- **行动**：在现有清洗和 mask 基础上增加技能、证据、质量、监督 token 与来源字段；合并轨迹/任务两侧家族并求闭包；排除历史曝光及跨集合近似题面。人工审计分层小样本，统计标签分歧和 unknown。
- **拟建接口**：`build_pool`、`audit_splits`、`annotate_skills`、`audit_skill_evidence`，输出稳定 ID 和数据内容 hash。
- **交付**：冻结池与 split manifest、技能 schema/证据表、标签审计、每技能可用量与约束可行性报告。
- **验收**：ID 不同但同来源家族仍被拦截；仅轨迹侧有来源也能识别；修改一条监督 token 会改变身份；标签证据缺失不允许升级为高置信标签；样本不足直接报不可行。
- **禁止**：向控制器暴露 final 题面/答案；复制补齐；根据模型成绩剔除困难题；用旧选择成员冒充新清洗抽样。

### M04｜模型、状态、事件与缓存身份

- **依赖**：M02–M03。
- **行动**：实现第 5.2 节核心数据对象、只追加事件、原子发布和 lineage。分开 accepted model、当前角色记忆、候选模型和缓存。基于实际 tokens/labels、adapter、投影、奖励和标签构造缓存键。
- **交付**：`contracts.py`、`registry.py` 和小型手工 fixture；事件 schema、发布/撤销规则。
- **验收**：换 adapter、tokenizer/template、mask、投影、开发 rollout、奖励或标签后相关缓存失效；同身份重复请求命中且不重算；损坏证据明确拒绝；不同内存状态有不同 state hash。
- **并发语义**：候选目录写完并校验后再发布；读者永不读取半写 adapter。接受指针用预期父 hash 比较并原子更新，恢复不二次提交。

### M05｜DSL、算子与确定性子集物化

- **依赖**：M03–M04。
- **行动**：实现第 5.3 节第一批算子；schema 校验、canonicalize、结构 hash、资源上限；输出成员、顺序和中间过滤理由。pack_budget 同时验证完整轨迹、监督 token 与 batch 整除。
- **交付**：`program.py`、`operators.py`；至少一个固定筛选程序、一个带技能分支程序、一个不可行程序及其实际输出。
- **验收**：同输入/seed 逐成员和顺序可复现；算子顺序改变的反例成立；未知字段/任意代码拒绝；配额不足不重复补齐；结构变化与参数变化可分别识别；同成员不同程序去重后可避免重复特征计算。
- **停止条件**：若第一版无法表达 E2 的固定规则、调参和结构修订三类条件，先修 DSL，不进入角色层。

### M06｜分技能自由执行、目标梯度与特征服务

- **依赖**：M03–M04；真实执行仍依赖服务器 smoke。
- **行动**：用统一 Agent/官方 harness 执行 D_dev，生成 CapabilityReport；重放实际输入/生成 token，按技能构造方向；按需计算未缓存候选的 LoRA 特征。接受新模型后以新 adapter 身份重新生成开发反馈与目标，不把旧梯度视为精确特征。
- **交付**：`evaluation.py`、`features.py`；开发逐题结果、技能方向与 coverage、缓存 manifest、串行/分片对照。
- **验收**：手算小向量对照；失败为零但固定分母；零向量保持零；底座 grad=None；评分前后所有参数不变；实际生成 logprob/重放一致；分片汇总不混合候选；全零方向阻止下一步。
- **缓存细节**：拒绝且模型不变时可复用同身份目标和特征；若协议要求新 rollout，则 rollout 身份变化必须重新生成相应目标。明确哪一种，不在恢复时临时决定。

### M07｜确定性 Leval 代理与约束报告

- **依赖**：M05–M06。
- **行动**：实现 q_ik、U(S)、硬约束与可行性报告；支持查询一个固定子集的实际效用。Leval 角色只能调用该报告，不改变规则。
- **交付**：`utility.py`；每技能贡献、权重、coverage、token 偏差、重复/来源/技能约束、成本字段。
- **验收**：与显式逐样本公式一致；固定约束直接 NICE 与 Ours 使用同一评价器；缺项/NaN 不返回合法分数；选择改变会真实改变聚合；样本均值代理与 batch Adam 明确分开。
- **新增风险检查**：用几组微型真实 CPU 更新对照代理的方向符号，确认 NLL/收益的正负约定；不能用本模块自己生成的结果当“独立真值”。

### M08｜三角色调用、prompt 和记忆

- **依赖**：M04–M07。
- **行动**：实现 Lopt 提案、Lexec 调用物化、Leval 调用数值报告和结构化反馈；隔离记忆，显式规定可见字段。共享同 accepted adapter，角色不能访问 final 或接受规则的写接口。
- **交付**：`roles.py`、三份版本化 prompt、工具 schema、request/response/parsed 输出与 token 成本记录。
- **验收**：mock 用脚本响应覆盖合法、无效、修复与拒绝；全部角色模型 hash 一致；记忆隔离；无效输出占预算；LLM 文字不能覆盖数值结果；角色无法调用训练或终测工具。
- **对照例外**：FC/E5 按已登记的角色模型映射验收，不要求它们强行共享学生权重；仍严查学生特征与训练起点一致。
- **边界**：权限通过明确工具视图和输入过滤实现；不能仅在 prompt 中写“不要看 final”就声称完成隔离。

### M09｜固定 checkpoint 的内层搜索

- **依赖**：M05–M08。
- **行动**：连接提案、校验、物化、取特征、评估、反馈与停止；维护实际已评价集合和 best_feasible；等价子集不重复昂贵计算，调用成本照实记。
- **交付**：`search.py`、搜索事件表、最好程序/子集/分数/证据引用、终止原因。
- **验收**：始终不触发 optimizer.step；全无效返回 NoFeasibleSelection；返回子集确实被评估；固定脚本下早停/预算停止精确；恢复后不增加已完成评价次数，不重新选另一个“最好”结果。
- **停止条件**：没有可行子集就结束这次外层尝试，保留原因；不回退到未经预先登记的随机子集。

### M10｜外层 SFT、接受/拒绝与角色切换

- **依赖**：M04、M06、M09，复用现有训练能力。
- **行动**：从 accepted adapter 建候选分支；按冻结 token/batch/优化器策略训练；相同 D_dev 配对评测；执行固定规则；发布接受指针或保留原模型。无论接受还是拒绝，都追加真实预测/实际反馈到准许的角色记忆。
- **交付**：`outer.py`、TrainReceipt、前后报告、AcceptanceDecision、adapter lineage 与角色绑定记录。
- **验收**：CPU 微型模型完成真实更新、保存和重载；拒绝后 accepted 参数逐值不变；接受后任务模型和三个角色全部切换；候选优化器不污染父状态；状态切换中断后恰好发布一次；真实失败不能通过 mock 注入改写为接受。
- **对照一致性**：所有方法具有相同阶段边界和优化器重置策略；固定子集也分阶段保存和评测，避免分段训练成为混杂。

### M11｜调度、恢复、失败分类与成本总账

- **依赖**：M04、M09–M10；与各模块逐步集成。
- **行动**：扩展现有服务/GPU/租约管理；梯度阶段与推理驻留按容量计划切换；冻结单卡任务槽、服务序列化和 adapter 身份屏障。将训练、开发 rollout、梯度、角色、拒绝、容器判分、装载及重试成本写入总账。
- **交付**：`schedule.py`、阶段 DAG、资源计划、恢复命令、cost ledger。
- **验收**：注入梯度缓存发布前、训练更新边界、adapter 发布、开发评测完成、接受指针写入、报告写入六类中断；恢复后成员、分数、adapter、计数与预算不变，未重复已完成任务。坏 checksum 保留并停止。
- **失败规则**：模型失败保留固定分母；基础设施错误最多两次重试且跨恢复累计；超限非空补丁送官方测试；只清理本运行拥有的进程/容器，不全局 prune。
- **成本规则**：GPU 时间按实占设备累计；并发时总 GPU 小时与墙钟分别报告。不能以 episode 秒数总和冒充经过时间，不能将逻辑 token 当 FLOPs。

### M12｜基线接口、E1 校准与端到端试点

- **依赖**：M03–M11；真实试点需事先冻结试点协议并获新增预算授权。
- **行动 A：CPU 与 mock**：实现统一 Selector 接口，跑完整 A 兼容回归与 RSI 全流程 mock。小 fixture 用于精确断言；另按拟正式规模生成全尺寸 mock，验证计数、调度、恢复、audit、CSV/PNG、zip。mock 必须同时覆盖接受和拒绝路径。
- **行动 B：E1**：先实现高/中/低和多个随机子集，匹配来源、长度、训练 token 和起点；保存每个实际子集的代理值；独立分支真实短训后在 D_dev/D_probe 评估。不要只训练“看起来最好”的子集。
- **行动 C：真实试点**：先单外层尝试打通，资源允许再测试少量顺序尝试；测梯度 coverage、估值与收益、程序有效率、缓存命中、吞吐、判分和接受链。自然拒绝不强求，真实统计不能注入预设成功。
- **交付**：试点报告、全尺寸 mock 证据、E1 原始表、成本模型、最终协议候选、主方法表和最终输出模型选择规则。
- **验收**：链路和身份可信；若代理失败、几乎全零或算力不可承受，给出修正/缩小研究范围方案，不能直接宣布完整 RSI 可行。正式预算与超参在看 D_final 前冻结。

### M13｜核心实验：主表、E2 与 E3

- **依赖**：M12 正式协议冻结和执行授权。
- **行动**：按第 7 节方法矩阵，从共同新初始 adapter 独立执行各方法/replicate。所有方法共享候选池、开发集、预算与工具协议；阶段适应性基线也按相同步数和次数训练。先完成开发链与最终 checkpoint 选择，不读取 D_final。
- **交付**：各方法完整选择记录、参数 lineage、每阶段开发反馈、训练/搜索成本、最终模型冻结清单候选。
- **验收**：E2 能分辨信号刷新、参数调节与结构改变；E3 区分固定成员、预设课程和反馈选择；程序结构变化有 AST 证据，不能只凭角色文字宣称发现结构。
- **边界**：不得看某方法的 final 结果后补训对手或调高 Ours 的预算。偶然失败与无效程序也记成本，不能只保留接受成功的链。

### M14｜E5：固定学生的新旧控制器交叉实验

- **依赖**：M12 的设计冻结、M13 的可用 accepted checkpoint；所用新控制器按预先规则挑选。
- **行动**：固定参考学生、候选池、能力报告、目标梯度、工具、预算、prompt 版本和搜索停止规则，只替换 Lopt 的旧/新权重；先固定 Lexec/Leval，再可选整套角色替换。对两种控制器提供相同基础记忆，另设相同历史记忆条件。
- **交付**：控制器身份、相同输入 checksum、各自程序/子集、从同一参考学生独立短训的收益、程序可行率和总成本。
- **验收**：参考学生和优化器策略完全一致；新旧控制器得到字节一致的能力/历史材料；不能用新控制器自己的学生继续训练后与旧学生比较；不能根据 final 成绩挑“最好控制器”。
- **结论约束**：只有估值更高或学生更强都不够；需要选中数据的实际学习收益。没有优势也交付负结果，收缩到反馈/记忆层面的结论。

### M15｜按优先级补充机制与扩展

- **E8**：先做分技能负迁移和标签人工审计；有无拒绝机制对照、第二模型和 General 属扩展预算，单独冻结，不默认执行全部。

- **验收**：冻结前不存在 D_final 运行反馈；所有方法共享相同任务及协议；测试完成后不据此换题、调参、选模型或重试模型失败。缺失/基础设施错误未解决则 completion 不能 completed。
- **异常边界**：若终测后发现改变研究语义的代码错误，保留该次全部证据并标记受影响比较。修复后的新运行需新身份；已看过的 final 不再包装为从未使用的盲测。工程中断恢复仍遵守冻结协议。

## 7. 实验矩阵：先回答哪些问题

### 7.1 E1 与当前 A 的关系

A 是现成的前置诊断，不是原稿 E1 的完整实施。A 没有多个独立高/中/低/随机子集，也没有足够的子集层重复来估计排名与学习收益的相关性。A 选中节点不一致，还会引入不同实际训练曝光。

RSI 的 E1 应在新实验内部独立执行：

1. 固定一个共同学生、优化器策略、候选池、目标梯度和工具协议。
2. 按高/中/低代理分数及随机选择产生多个子集；在完整轨迹、来源、token 与长度上尽量匹配，并记录残余差异。
3. 每个实际子集都保存 q、U、成员、顺序和 token 数，从同一学生独立训练。
4. 用 D_dev 和 D_probe 评测，D_probe 此后视为开发数据；D_final 不用于决定是否扩展。
5. 先比较统一训练终点；若要选节点，所有子集使用相同、预先定义的开发规则，且相关性分析明确受此选择影响。

可将“高/中/低各 3 子集，另 3 随机，共 12 个短训分支”作为**成本试算示例**，不是正式必跑数。实际重复数由试点方差、最小关注效果和可用算力决定；只有很少子集时只作探索性散点和区间，不用一个相关系数承诺机制成立。不同子集共享训练样本和评测任务，相关性须报告。

E1 的通过标准不是必须显著正相关。需要确认实现可信，判断代理能否提供足够稳定、具有成本价值的区分；若不能，先排查奖励覆盖、符号、目标噪声、投影和 optimizer 失配。修订代理后重新冻结并校准，不能看 final 选最有利版本。

### 7.2 精简主表与消融

| 代号 | 方法 | 信号刷新 | 程序变化 | 用于回答 |
|---|---|---|---|---|
| B0 | 共同初始模型 | 无训练 | 无 | 训练前能力 |
| B1 | 质量准入后的 token 匹配随机选择 | 按冻结阶段抽样方案 | 无 | 复杂选择是否优于朴素基线 |
| B6 | 直接 NICE 排序/约束贪心 | 每阶段按当前学生刷新 | 固定选择算法 | 程序搜索是否超过同信号直接选数 |
| S0 | 初始冻结程序和成员，按阶段继续训练 | 不刷新 | 无 | E2 固定策略；E3 固定子集 |
| S1 | 固定程序，每阶段刷新模型侧分数 | 是 | 无 | 仅刷新分数是否已足够 |
| S2 | 固定结构，仅调整权重/阈值/配额 | 是 | 仅参数 | 结构修订是否有额外价值 |
| C0 | 初始时预先生成分阶段课程 | 仅使用初始可见信息规划 | 后续不根据新反馈改计划 | E3 预设课程 |
| Ours | 当前模型按反馈修订程序 | 是 | 算子/顺序/分支/参数 | 完整方法 |
| FC（优先补充） | 控制器始终用初始权重，学生继续学习 | 学生信号刷新；历史按同规则更新 | 控制器仍可修订程序 | 控制器权重更新与反馈/历史区分 |

B1 的“每阶段重新随机抽样”或“初始一次抽完再分段”必须明确，两者不能混成同一个基线。可分别作为动态随机与固定随机对照，新增行时计入预算。

S0 的初始程序和成员用共同初始条件产生；若每个方法自己的初始搜索不同，不能声称后续差异仅来自动态反馈。C0 的所有阶段计划在训练前物化并保存，不能运行到中途调用新能力报告。

B2 的“全池中均匀抽 token 匹配数据”若与 B1 相同，不重复算一项独立强基线。真正全池 SFT 使用更多训练 token，作为额外数据/成本参照单列，不与预算匹配主表混称公平胜负。

LESS、NLL/entropy、多维质量选择、AutoSelection 适配可分阶段加入，优先保证 B1、B6、S0/S1/S2、C0、Ours 和关键控制器对照。第一版不必同时承担原稿所有 B0–B8 的实现成本。删减理由与未覆盖比较必须在正式冻结前写明。

所有方法均遵守相同质量准入、token、去重、来源/技能覆盖约束。直接 NICE 的求解器使用确定性贪心或已锁版本的约束优化；若采用近似求解，报告未满足或近似的部分。不要把 Ours 的额外硬约束当作它优于一个无约束 NICE 的证据。

### 7.3 E2：结构变化必须有可检查的定义

对 Program 计算两个签名：

- `structure_signature`：保留算子类型、拓扑、顺序、分支，去掉可调参数值。
- `parameter_signature`：在固定结构中记录阈值、权重、配额、seed 等。

S2 只能改第二个签名。Ours 可改两者。Ours 若最终只修改了参数，结果仍有效，但只能说明本次搜索采用了参数调节，不能写“发现了新程序结构”。同时报告可行程序比例、等价子集比例、重复失败与结构变化次数。

### 7.4 E3：阶段适应性与训练顺序

S0、C0、Ours 共享阶段数、每阶段训练 token、优化器规则、开发评测次数与最大尝试预算。固定成员也分阶段训练；预设课程与反馈选择都保留相同的断点边界。

若加“相同成员、打乱顺序”的机制实验，必须固定数据成员与曝光次数，仅改变顺序。不同成员方法的差异不能全部解释成课程顺序作用。拒绝分支仍计入实际训练成本，另报告接受链长度。

### 7.5 E5：最小有辨识力的交叉设计

| 控制器 | 提供的记忆 | 固定学生与证据 |
|---|---|---|
| θ_old 的 Lopt | 相同基础记忆 M0 | 完全相同 θ_ref、池、能力报告、目标梯度、工具与预算 |
| θ_new 的 Lopt | 相同基础记忆 M0 | 同上 |
| θ_old 的 Lopt | 相同历史摘要 H | 同上 |
| θ_new 的 Lopt | 相同历史摘要 H | 同上 |

先只替换 Lopt，其他角色固定；资源允许再替换整套控制角色。H 对两种权重提供完全相同文本，不能让新权重多看一段成功经验。

每个控制器选出的子集，都从同一 θ_ref 独立 SFT 后比较实际收益。优先报告配对 D_probe 收益；若 E5 要作确认性 final 比较，必须在 M12 就登记这些学生输出模型，统一进入 M16，不能事后临时追加终测。

θ_new 建议按冻结规则取“固定尝试预算结束后的最后 accepted checkpoint”，不用 final 最优。若整个链没有接受任何新模型，就如实记录“无法形成新旧权重比较”，不能虚构一份更新模型完成 E5。

## 8. 统计、图表与证据交付规范

### 8.1 统计单位与主比较

正式冻结前写清主比较，例如 Ours 对 B6、Ours 对 S2；其余作为次要或探索比较。不要直到看结果后才挑最显著的一对。

- 最终成功率：逐任务 resolved/固定 N，同时报告成功数和分母。
- 方法差异：共享题目的配对提升、双方独赢/独输/同成/同败计数；置信区间按任务配对重采样。若任务存在明显来源家族聚类，采用家族块重采样或另报敏感性分析。
- 训练重复：有多个 replicate 时按 replicate/任务层次报告；一个 seed 时只报告任务抽样不确定性，不能称训练随机性稳定。多个 checkpoint、学习率和 rollout 不是独立 replicate。
- 可选检验：预先指定的二项配对比较可用 exact McNemar；多个确认性比较预先定义校正族，例如 Holm。小样本不显著不代表方法等效。
- E1：子集为估值—收益关系的分析单位；保存原始散点、Spearman 和区间。常数序列/并列过多时相关性给 null/说明，不生成虚假精度；共享任务、子集重叠和训练重复的依赖单独说明。
- 技能：按固定标签报告每技能分母、目标/保持表现和退化；多标签分组不是互斥样本，不把各技能人数相加冒充独立总量。
- 多次开发：开发选择成绩标注适配性；只在未用于选择的 final 上报告独立泛化证据。

1. E1 每个实际子集的代理—学习增益散点，区分分档与随机，显示不确定性。
2. 主表方法的成功率及配对差异；分类方法之间不连接折线。
3. 逐外层尝试的开发表现与接受/拒绝；横轴同时给出实际训练 token 或总成本。
4. 程序结构变化与选择分布，区分参数变化和拓扑/顺序变化。
5. E5 新旧控制器在相同学生上的实际收益与可行程序率。
6. GPU 小时/总成本—收益曲线，拒绝和失败成本包括在内。
7. 按技能的提升/退化与低覆盖标记；可选 E4 checkpoint×程序热图。

正式出图使用色盲安全配色和冗余标记，检查灰度版、缺字、裁切、遮挡。图中展示全部小样本点，不用均值柱掩盖分布。本次仅规划图表，不生成实验数据或科学成图。

### 8.4 研究与工程完成状态

建议完成状态至少区分 `draft`、`cpu_verified`、`mock_verified`、`server_smoke_passed`、`formal_running`、`formal_completed`、`failed`。

`formal_completed` 要求：真实模式、完整固定分母、所有模型身份与判分证据可验、审计无 FAIL、zip 验证通过。mock 的正式 success_rate、delta、相关性等保持 null；可另有明确 synthetic 字段。不要把 mock 的预设接受次数写进研究结论。

报告至少包含“研究结果、工程状态、协议偏离、未知项”。原始数据、模型、LoRA、优化器、完整 trace 和投影缓存留服务器；小结果包提供路径索引与 checksum。凭据不写入任何报告。

## 9. 资源预算与进度安排

### 9.1 先测量，再承诺完成时间

M01/M12 测量：模型装载、长序列 NICE 前反向、每条候选特征、SFT 监督 token/s、开发/终测 episode 分位耗时、容器准备与官方判分吞吐、角色调用 token/s、缓存命中。记录真实 UUID、并发、内核、峰值显存和软硬件版本。

成本估算至少分开：

```text
C_total = C_prepare + C_smoke + C_target_rollouts + C_target_backward
        + C_candidate_features + C_roles + C_all_SFT_attempts
        + C_dev_eval + C_final_eval + C_grading
        + C_failed_attempts_and_retries + C_load_and_switch
```

各项口径互斥，避免把一次含判分的 episode 成本又加一遍判分成本。输入/输出 token 与 GPU 小时是不同维度，不相加成没有单位的“总分”。没有电价/租赁单价就报告 GPU 小时与墙钟，美元费用保留未知。

实际计划计数由 manifest 推导：

```text
最终 episode = N_final × 最终释放清单中的不同模型数
开发候选评测 = N_dev × 所有实际候选模型数（另加未缓存父模型评测）
目标 rollout = Σ_需要新目标的 accepted_model_ref N_dev × M
候选梯度条数 = Σ_模型身份下被查询候选的去重并集大小
训练 token   = Σ_全部尝试实际监督 token（包括拒绝）
```

这些是计数模板，实际实现需处理父模型评测复用、目标刷新策略和方法间共同初始点去重，不能凭公式覆盖不同运行身份下的旧结果。磁盘还应估计完整请求/响应/工具观察、容器层、optimizer/RNG 断点及长序列 trace，不能只估投影向量大小。

两个公平视角分别报告：

- **同实际 SFT 预算**：各方法最大尝试次数与每阶段监督 token 匹配，搜索成本另报。
- **同总资源上限**：所有方法计入自身搜索/梯度/开发/拒绝等开销，达到上限即停，比较当时已接受模型。优先从预设检查点与成本日志构建曲线；没有对应真实模型时不插值制造成绩。

### 9.2 推荐里程碑与投入优先级

| 里程碑 | 模块 | 交付后作出的决定 |
|---|---|---|
| G0：可信起点 | M00–M01 | A 实测是否完成，哪些接口/容量仍未验 |
| G1：可执行选择器 | M02–M07 | 数据与代理能否支持约束筛选，是否存在可行子集 |

| G3：真实可行性 | M12 | E1 和成本是否支持继续；冻结哪些方法、规模和预算 |

## 10. 严肃执行所需的工程纪律

1. 研究源码变化后跑全量 pytest；流程变化另跑全尺寸 fresh mock、串行评分对照、恢复、audit、CSV/PNG 与 zip 检验。只改本文档不需要重跑研究全流程。
2. 测试断言应有独立参考，例如手算向量、真实 CPU optimizer 更新、逐任务固定分母；不能直接复制实现公式作为唯一测试真值。
3. 修改现有共享模块时保留 A 回归；不能通过删测试、降低预算、移除身份校验或标记跳过来得到绿色。
4. 本地不启动真实模型/GPU/Docker；服务器必须核验明确 UUID、模型 revision、任务环境和完整容量。不自动改模型、学习率、训练轮数、上下文、量化或实验数据规模。
5. 正常依赖、路径、端口和授权范围内的工程修复自主处理并记录。改变研究语义、冻结源码或环境后新建运行身份与 storage，保留旧证据，不改 snapshot 恢复。
6. 相同基础设施错误最多两次重试；模型任务失败、无效程序、无可行子集、自然拒绝不是靠重试刷掉的基础设施错误。
7. 训练断点恢复 adapter、optimizer、RNG、顺序和有效 batch；未知工具动作从干净容器重启整个未完成 episode，不重放有副作用的历史动作。
8. 不自动 commit/push/merge。数据、权重、缓存、凭据、运行状态与本地报告不提交到 Git；规格文档与源码可由用户自行审阅后提交。
9. 不在看到 benchmark 后换题、调参、重选模型或扩大 Ours 搜索；终测反馈不进入后续控制器记忆。
10. 任何“完成”同时说明实现、测试、真实验收与研究结果四种状态，不用“整体应该没问题”替代证据。

## 11. 交给 Codex 的启动方式

先发送配套 [任务卡文件](RSI_CODEX_TASKS_ZH.md) 的“总指令”，再发送 M00。每轮指定当前模块及允许模式，例如 `M05，CPU/mock 实现，遵守本计划第 6 节验收`。不要只发送“照计划全部做完”，也不要每一步手动重新解释研究目标。

模块完成后 Codex 应主动继续当前已授权阶段中的下一个模块，并维护状态清单。若缺服务器访问，可继续独立 CPU 工作；若缺新研究授权，先把协议、数据可行性、成本与可审阅配置准备完整，不跨越该节点。

建议模块交接固定为六项：

```text
模块与状态：
实现/运行了什么：
证据文件和身份：
测试与验收结果（CPU/mock/server 分开）：
未完成项、阻塞与协议偏离：
下一步的具体命令或模块：
```

此方式能减少“代码写了一大半，最后发现数据隔离、预算、公平比较或恢复语义不成立”的返工。计划保证步骤可审查和失败可追溯；它不保证实验一定得到正向结果，也不能替代服务器真实验收。
